# BudgetManagementBotSystem — 運用資料

このドキュメントは、実装済み Discord コマンドの運用上の使い分けと実務での扱いをまとめます。

対象のコマンド一覧や実装状況の全体像は [実装状況](implementation.md) を参照してください。

## 運用の考え方

実運用では、次の 4 つの観点でコマンドを使い分けます。

- 初期設定と権限付与
- 予算申請と証跡添付
- 承認・却下・取消などのワークフロー操作
- 班・ユーザー・予算の管理操作

## 初期設定と権限付与

- `/become-admin` は、`AdminBootstrap:Password` を使って自分を管理者に昇格する初期化コマンドです。
- 初回運用時の管理者登録に使う想定で、通常運用では頻繁に実行しません。
- ユーザー登録や権限変更、班管理系のコマンドは、登録済みユーザーかつ管理者権限が必要です。

## 予算申請の運用

- `/create-request` は、班 ID、金額、説明、証憑ファイルを指定して申請内容の確認 UI を表示します。
- 申請先は、システムに登録されている自身の所属班に限られます。候補に他班が表示されても、その班への申請権限を意味しません。管理者・会計担当などの役職でもこの所属条件は同じです。
- 所属班と申請先が異なる場合や所属が未設定の場合は、確認画面に進む前に、登録されている所属班・申請先・拒否理由・対処方法を本人だけに表示します。所属班を選び直すか、登録内容が実際と異なる場合は管理者に `/assign-group` による確認・修正を依頼してください。時間を置いて再実行しても所属の不一致は解消しません。
- 「申請する」を押した時点でも最新の所属を再確認します。確認途中で所属が変更・解除された場合も同じ案内を表示し、申請や証憑ファイルを保存しません。
- 証憑ファイルは `evidence-1` が必須、`evidence-2` から `evidence-5` は任意です。Discord で添付可能なファイルであれば、拡張子や ContentType を理由に拒否しません。
- 証憑ファイルは1ファイルあたり10MB以下、最大5件までです。ファイル名が空、0バイト、ダウンロード失敗の場合は登録できません。
- ファイル種類を制限しないため、添付ファイルを開く際は、送信者と内容を確認してください。Bot 側ではファイル内容の安全性までは保証しません。
- 確認 UI の「申請する」を押すまで申請は作成されません。「キャンセル」を押した場合も申請は作成されません。確認は10分で期限切れになります。
- 申請が作成されると、会計担当者には DM で通知されます。
- `/request-detail` は申請の詳細、証跡、状態履歴を確認するための参照コマンドです。会計担当者が承認待ち申請を表示した場合のみ「承認」「却下」ボタンからその場で処理できます。
- `/request-detail` は数値の申請 ID を受け付けた時点で応答を保留し、データ取得・証跡送信後に結果を表示します。証跡の送信に3秒以上かかる場合も初回応答の期限切れを防ぎます。詳細と同様、受付後の対象なし・取得失敗の案内はコマンド実行先に表示します（内部例外は表示しません）。数値以外の ID の入力エラーは実行者にのみ表示します。
- `/list-requests` は申請一覧をページング付きで確認するための運用コマンドです。2ページ以上ある場合は、Embed下部の「前へ」「更新」「次へ」ボタンでページ移動できます。
- `/cancel-request` は、申請者自身による取消と、権限保持者による取消の両方に対応しています。

## 承認フローの運用

- `/pending-list` で未承認申請を確認します。2ページ以上ある場合は、Embed下部の「前へ」「更新」「次へ」ボタンでページ移動できます。
- `/approve` で申請を承認できます。承認時は申請者に DM 通知を送ります。
- `/reject` で申請を却下できます。却下時は理由を入力し、申請者に DM 通知を送ります。
- `/request-detail` のボタン操作でも、同じ承認・却下処理と申請者 DM 通知が実行されます。ボタンは会計担当 (`Accountant`) にのみ表示され、却下ボタンでは理由入力用のModalが表示されます。
- `/revoke-approval` は、承認済み申請の承認を取り消すために使います。
- これらのコマンドは、対象の申請 ID を基準に処理されるため、一覧や詳細確認と組み合わせて使うのが前提です。

## 予算参照と増額の運用

- `/remaining-budget` で現在の残予算を確認します。
- `/usage-history` で班ごとの予算使用履歴を追跡します。2ページ以上ある場合は、Embed下部の「前へ」「更新」「次へ」ボタンでページ移動できます。
- `/all-history` は全班の履歴を広く確認したいときに使います。
- `/remaining-budget` と `/usage-history` の `group-id` は、所属班が一つなら省略可能です。未所属・複数所属の場合は表示する班を指定する案内を返します。履歴のページ送りは、最初に表示した班を維持します。
- `/add-budget` は追加予算を反映するコマンドで、管理者または権限保持者のみ実行できます。

## 班・ユーザー管理の運用

- `/register-group` と `/delete-group` で班を追加・無効化します。
- `/list-groups` は登録済み班の確認に使います。
- `/register-user` で Discord ユーザーをシステムに登録し、`/set-user-name` で表示名、`/set-user-role` で権限を設定します。
- `/remove-user` はユーザーを無効化し、`/activate-user` は無効化済みユーザーを再有効化します。
- `/assign-group user-id:<ユーザーID> group-id:<班ID>` で所属班を追加します。複数の班に所属でき、追加しても既存の所属は残ります。同じ班への再実行は重複を作りません。
- `/unassign-group user-id:<ユーザーID> group-id:<班ID>` は指定班への所属だけを解除します。対象班を省略した場合は案内を返し、所属は変更しません。所属先を置き換える場合は、新しい班への追加と以前の班の解除をそれぞれ実行してください。
- 登録済みのどの所属班にも `/create-request` で申請できます。未登録の班への申請は、登録されている所属一覧と追加手順を本人だけに案内します。
- `/list-users`、`/user-info`、`/group-members` は、運用確認や問い合わせ対応で使う参照系コマンドです。

## 運用時の注意点

- 多くの管理系コマンドは `ephemeral` 応答を返すため、実行者以外には見えません。
- スラッシュコマンド登録は既定で `Guild` です。単一サーバー運用では `Discord:GuildId` を設定し、起動時に現在のコマンドだけを `deleteMissing=true` で登録します。
- `Global` 登録を使う場合、Discord 側の反映に時間がかかることがあります。古い表示から廃止済みコマンドが実行された場合でも、Bot は通常処理に入る前に ephemeral メッセージで案内して終了します。
- ユーザーがシステムに未登録の場合、申請・承認・参照の一部は失敗します。
- `/create-request` では Discord の添付引数を使うため、申請時に証憑ファイルを直接指定してください。確認 UI のボタンを押せるのは申請者本人のみです。
- 一覧系ページングボタンを押せるのは、その一覧を表示した本人のみです。ページング操作のセッションは15分で期限切れになります。
- 申請者、会計担当者、管理者の責務を分けて運用すると、承認・取消・参照の権限管理が追いやすくなります。

## コマンド別の利用権限

以下は実装上の権限要件（要約）です。実際の判定は各 UseCase / AuthorizationHelper に従います。

| コマンド | 説明 | 実行可能な権限 |
|---|---|---|
| `/become-admin` | パスワードで自分を管理者に昇格 | `AdminBootstrap:Password` を知る者（初回の管理者登録用） |
| `/create-request` | 予算使用申請を作成 | システムに登録されたユーザー。自身の所属班への申請のみ |
| `/request-detail` | 申請の詳細・証跡を表示 | システムに登録されたユーザー（実装上の追加制限なし） |
| `/list-requests` | 申請一覧の取得（ページング） | 管理者/会計/会長: 全班参照、班長: 所属する全班。班指定時はその班に絞る |
| `/cancel-request` | 確認待ち申請の取消 | 申請者（自身の Pending のみ）または管理者 |
| `/pending-list` | 未承認申請の一覧表示 | 管理者/会計/班長/役員: 全件、一般ユーザー: 自班のみ |
| `/reject` | 申請の却下。理由入力と申請者 DM 通知あり | 会計担当 (`Accountant`) の権限が必要 |
| `/approve` | 申請の承認。申請者 DM 通知あり | 会計担当 (`Accountant`) の権限が必要 |
| `/revoke-approval` | 承認済み申請の承認取り消し | 会計担当 (`Accountant`) の権限が必要 |
| `/remaining-budget` | 班の残予算を表示 | システム登録ユーザー。`group-id` で対象班を指定 |
| `/usage-history` | 班ごとの予算使用履歴 | システム登録ユーザー（既定で自身の班） |
| `/all-history` | 全班の予算履歴表示 | 実装上は特別な権限制御なし（運用で制限を推奨） |
| `/add-budget` | 追加予算の付与 | 管理者 (`Admin`) または 会長/役員相当 (`President`) |
| `/register-group` | 新しい班の登録 | 実装上は制限なし（運用上は管理者限定を推奨） |
| `/list-groups` | 登録済み班一覧表示 | システムに登録されたユーザー |
| `/delete-group` | 班の削除／無効化 | 管理者 (`Admin`) のみ |
| `/register-user`, `/set-user-name`, `/set-user-role`, `/remove-user`, `/activate-user`, `/list-users`, `/assign-group`, `/unassign-group`, `/user-info` | ユーザー登録・表示名変更・権限設定・有効/無効化・参照等 | 管理者 (`Admin`) のみ |
| `/group-members` | 指定班のメンバー一覧 | 管理者/会長: 任意班参照可能、その他: 所属するいずれかの班 |

上記はソースコードの現状に基づく要約です。運用ポリシーに合わせて、各 UseCase または `AuthorizationHelper` を変更してください。

## UI表示方針

- 主要なDiscordコマンドの応答はEmbed表示に統一しています。
- 成功は緑、通常情報は青、注意・入力確認は金、エラー・失敗は赤、取消・無効化系は灰色またはオレンジで表示します。
- 入力不備、権限不足、対象なし、予期しないエラーは共通Embedで表示し、内部例外の詳細はDiscord上に直接表示しません。
- 一覧系のコマンドはDiscord Embed制限を考慮し、表示件数が多い場合は一部のみ表示し、ページ情報や総件数をEmbed内に表示します。`/usage-history`、`/list-requests`、`/pending-list` は2ページ以上の結果でページングボタンを表示します。
- `/menu` はログインユーザーのRoleに応じて利用可能な主要コマンドをEmbedで表示します。
