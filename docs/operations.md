# BudgetManagementBotSystem — 運用資料

このドキュメントは、実装済み Discord コマンドの運用上の使い分けと実務での扱いをまとめます。

対象のコマンド一覧や実装状況の全体像は [実装状況](implementation.md) を参照してください。

## 運用の考え方

実運用では、次の 4 つの観点でコマンドを使い分けます。

- 初期設定と権限付与
- 予算申請と証跡添付
- 承認・却下・取消などのワークフロー操作
- 班・ユーザー・予算の管理操作

## 初期設定と権限付与

- `/become-admin` は、`AdminBootstrap:Password` を使って自分を管理者に昇格する初期化コマンドです。
- 初回運用時の管理者登録に使う想定で、通常運用では頻繁に実行しません。
- ユーザー登録や権限変更、班管理系のコマンドは、登録済みユーザーかつ管理者権限が必要です。

## 予算申請の運用

- `/create-request` は、班 ID、金額、説明、添付数を指定して申請を作成します。
- 実行後は同じチャンネルで証跡ファイルのアップロードを待機し、30 秒以内に必要件数が揃わない場合は中止します。
- 申請が作成されると、会計担当者には DM で通知されます。
- `/request-detail` は申請の詳細、証跡、状態履歴を確認するための参照コマンドです。
- `/list-requests` は申請一覧をページング付きで確認するための運用コマンドです。
- `/cancel-request` は、申請者自身による取消と、権限保持者による取消の両方に対応しています。

## 承認フローの運用

- `/pending-list` で未承認申請を確認します。
- `/approve` と `/reject` で申請を承認・却下します。
- `/revoke-approval` は、承認済み申請の承認を取り消すために使います。
- これらのコマンドは、承認対象の申請 ID を基準に処理されるため、一覧や詳細確認と組み合わせて使うのが前提です。

## 予算参照と増額の運用

- `/remaining-budget` で現在の残予算を確認します。
- `/usage-history` で班ごとの予算使用履歴を追跡します。
- `/all-history` は全班の履歴を広く確認したいときに使います。
- `/add-budget` は追加予算を反映するコマンドで、管理者または権限保持者のみ実行できます。

## 班・ユーザー管理の運用

- `/register-group` と `/delete-group` で班を追加・無効化します。
- `/list-groups` は登録済み班の確認に使います。
- `/register-user` で Discord ユーザーをシステムに登録し、`/set-user-role` で権限を設定します。
- `/assign-group` と `/unassign-group` でユーザーの班所属を更新します。
- `/list-users`、`/user-info`、`/group-members` は、運用確認や問い合わせ対応で使う参照系コマンドです。

## 運用時の注意点

- 多くの管理系コマンドは `ephemeral` 応答を返すため、実行者以外には見えません。
- ユーザーがシステムに未登録の場合、申請・承認・参照の一部は失敗します。
- `/create-request` では添付待機が入るため、チャンネル運用ルールを事前に共有しておくとトラブルを減らせます。
- 申請者、会計担当者、管理者の責務を分けて運用すると、承認・取消・参照の権限管理が追いやすくなります。
