# BudgetManagementBotSystem — 運用資料

このドキュメントは、実装済み Discord コマンドの運用上の使い分けと実務での扱いをまとめます。

対象のコマンド一覧や実装状況の全体像は [実装状況](implementation.md) を参照してください。

## 運用の考え方

実運用では、次の 4 つの観点でコマンドを使い分けます。

- 初期設定と権限付与
- 予算申請と証跡添付
- 承認・却下・取消などのワークフロー操作
- 班・ユーザー・予算の管理操作

## 初期設定と権限付与

- `/become-admin` は、`AdminBootstrap:Password` を使って自分を管理者に昇格する初期化コマンドです。
- 初回運用時の管理者登録に使う想定で、通常運用では頻繁に実行しません。
- ユーザー登録や権限変更、班管理系のコマンドは、登録済みユーザーかつ管理者権限が必要です。

## 予算申請の運用

- `/create-request` は、班 ID、金額、説明、証憑ファイルを指定して申請内容の確認 UI を表示します。
- 証憑ファイルは `evidence-1` が必須、`evidence-2` から `evidence-5` は任意です。対応形式は jpg / jpeg / png / webp / pdf、1ファイルあたり10MB以下です。
- 確認 UI の「申請する」を押すまで申請は作成されません。「キャンセル」を押した場合も申請は作成されません。確認は10分で期限切れになります。
- 申請が作成されると、会計担当者には DM で通知されます。
- `/request-detail` は申請の詳細、証跡、状態履歴を確認するための参照コマンドです。
- `/list-requests` は申請一覧をページング付きで確認するための運用コマンドです。
- `/cancel-request` は、申請者自身による取消と、権限保持者による取消の両方に対応しています。

## 承認フローの運用

- `/pending-list` で未承認申請を確認します。
- 現行の Discord コマンドでは `/reject` で申請を却下できます。却下時は理由を入力し、申請者に DM 通知を送ります。
- `ApproveBudgetRequestUseCase` は実装済みですが、`/approve` スラッシュコマンドは現行の `ApprovalModule` では公開されていません。
- `/revoke-approval` は、承認済み申請の承認を取り消すために使います。
- これらのコマンドは、対象の申請 ID を基準に処理されるため、一覧や詳細確認と組み合わせて使うのが前提です。

## 予算参照と増額の運用

- `/remaining-budget` で現在の残予算を確認します。
- `/usage-history` で班ごとの予算使用履歴を追跡します。
- `/all-history` は全班の履歴を広く確認したいときに使います。
- `/add-budget` は追加予算を反映するコマンドで、管理者または権限保持者のみ実行できます。

## 班・ユーザー管理の運用

- `/register-group` と `/delete-group` で班を追加・無効化します。
- `/list-groups` は登録済み班の確認に使います。
- `/register-user` で Discord ユーザーをシステムに登録し、`/set-user-name` で表示名、`/set-user-role` で権限を設定します。
- `/remove-user` はユーザーを無効化し、`/activate-user` は無効化済みユーザーを再有効化します。
- `/assign-group` と `/unassign-group` でユーザーの班所属を更新します。
- `/list-users`、`/user-info`、`/group-members` は、運用確認や問い合わせ対応で使う参照系コマンドです。

## 運用時の注意点

- 多くの管理系コマンドは `ephemeral` 応答を返すため、実行者以外には見えません。
- ユーザーがシステムに未登録の場合、申請・承認・参照の一部は失敗します。
- `/create-request` では Discord の添付引数を使うため、申請時に証憑ファイルを直接指定してください。確認 UI のボタンを押せるのは申請者本人のみです。
- 申請者、会計担当者、管理者の責務を分けて運用すると、承認・取消・参照の権限管理が追いやすくなります。

## コマンド別の利用権限

以下は実装上の権限要件（要約）です。実際の判定は各 UseCase / AuthorizationHelper に従います。

| コマンド | 説明 | 実行可能な権限 |
|---|---|---|
| `/become-admin` | パスワードで自分を管理者に昇格 | `AdminBootstrap:Password` を知る者（初回の管理者登録用） |
| `/create-request` | 予算使用申請を作成 | システムに登録されたユーザー |
| `/request-detail` | 申請の詳細・証跡を表示 | システムに登録されたユーザー（実装上の追加制限なし） |
| `/list-requests` | 申請一覧の取得（ページング） | 管理者/会計/班長/役員: 全班参照、一般ユーザー: 自班のみ |
| `/cancel-request` | 確認待ち申請の取消 | 申請者（自身の Pending のみ）または管理者 |
| `/pending-list` | 未承認申請の一覧表示 | 管理者/会計/班長/役員: 全件、一般ユーザー: 自班のみ |
| `/reject` | 申請の却下。理由入力と申請者 DM 通知あり | 会計担当 (`Accountant`) または管理者 (`Admin`) の権限が必要 |
| `/approve` | 申請の承認 | UseCase は実装済みだが、現行スラッシュコマンドとしては未公開 |
| `/revoke-approval` | 承認済み申請の承認取り消し | 会計担当 (`Accountant`) の権限が必要 |
| `/remaining-budget` | 班の残予算を表示 | システム登録ユーザー。自班未設定で任意班参照は特権（Admin等）必要 |
| `/usage-history` | 班ごとの予算使用履歴 | システム登録ユーザー（既定で自身の班） |
| `/all-history` | 全班の予算履歴表示 | 実装上は特別な権限制御なし（運用で制限を推奨） |
| `/add-budget` | 追加予算の付与 | 管理者 (`Admin`) または 会長/役員相当 (`President`) |
| `/register-group` | 新しい班の登録 | 実装上は制限なし（運用上は管理者限定を推奨） |
| `/list-groups` | 登録済み班一覧表示 | システムに登録されたユーザー |
| `/delete-group` | 班の削除／無効化 | 管理者 (`Admin`) のみ |
| `/register-user`, `/set-user-name`, `/set-user-role`, `/remove-user`, `/activate-user`, `/list-users`, `/assign-group`, `/unassign-group`, `/user-info` | ユーザー登録・表示名変更・権限設定・有効/無効化・参照等 | 管理者 (`Admin`) のみ |
| `/group-members` | 指定班のメンバー一覧 | 管理者/会長: 任意班参照可能、一般ユーザー: 自班のみ |

上記はソースコードの現状に基づく要約です。運用ポリシーに合わせて、各 UseCase または `AuthorizationHelper` を変更してください。

## UI表示方針

- 主要なDiscordコマンドの応答はEmbed表示に統一しています。
- 成功は緑、通常情報は青、注意・入力確認は金、エラー・失敗は赤、取消・無効化系は灰色またはオレンジで表示します。
- 入力不備、権限不足、対象なし、予期しないエラーは共通Embedで表示し、内部例外の詳細はDiscord上に直接表示しません。
- 一覧系のコマンドはDiscord Embed制限を考慮し、表示件数が多い場合は一部のみ表示し、ページ情報や総件数をEmbed内に表示します。
- `/menu` はログインユーザーのRoleに応じて利用可能な主要コマンドをEmbedで表示します。
