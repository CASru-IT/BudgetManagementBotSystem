# 複数所属への更新手順

## 更新

1. 統合テストを含む `dotnet test` を空の独立した PostgreSQL で通す。
2. 現行イメージ・設定・接続先・マウントを記録し、DBのダンプと証憑ファイルをバックアップする。バックアップは管理者のみ読める場所に保管する。
3. Botのみ新イメージへ更新する。起動時に `EnsureCreatedAsync` の後で `MembershipSchemaUpgrade.ApplyAsync` が動く。
4. `UserGroupMemberships` と `__CasruSchemaUpdates` が追加され、従来の `Users.GroupId` が所属行へコピーされる。移行は advisory lock と一つのトランザクションで実行する。既存の所属・申請・金額・証憑は書き換えない。
5. 全ユーザーの移行済み所属と旧所属の一致、財務テーブル・証憑の保持、Bot起動・Discord接続・コマンド再登録を確認する。運用中の同時更新があれば差分を精査し、自動でDBを巻き戻さない。

移行済みの記録がある場合は旧列から再取り込みしない。起動を繰り返しても、解除した所属が復活しない。

## 切り戻し

追加テーブルと旧 `Users.GroupId` 列は共存するため、アプリと設定を旧版へ戻せる。DBダンプを自動復元してはいけない（更新後の正当な申請を失う可能性がある）。

旧版から見える所属は互換列に記録された一つだけで、複数所属の機能は使えない。切り戻し中は `/assign-group`・`/unassign-group` による所属変更を止めること。旧版で変更した場合、再更新前に管理者が所属表との差を確認して反映する必要がある。新旧Botの同時稼働は避ける。移行記録を削除して再取り込みさせる運用は行わない。
