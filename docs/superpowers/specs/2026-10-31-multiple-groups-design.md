# 複数班への所属

ユーザーは複数の班に所属でき、登録されたどの班にも申請できる。既存の所属をそのまま引き継ぐ。役職・承認権限は変更しない。

- `/assign-group` は追加。同じ班への再実行は重複を作らない。
- `/unassign-group` は対象班を指定して解除。他の所属は維持。班省略は案内だけ返し、変更しない。
- ユーザー情報、候補、メンバー一覧、申請拒否案内は複数所属に対応。
- 残予算・使用履歴は、班省略かつ所属が一つの場合だけ補完する。複数または未所属なら班の指定を促す。
- 申請一覧の所属限定閲覧は所属する全班を対象とする。班指定時は所属と指定の両方で絞る。既存の全班閲覧権限は維持。

`UserGroupMemberships` に `(UserId, GroupId)` の複合主キーを持つ。既存 `Users.GroupId` は互換列として残し、現行の所属判定には使用しない。所属追加・解除時には残る所属の一つ、または null を互換列に保存する。旧版への切り戻し時にはこの一所属だけが見える。

起動時にトランザクションと PostgreSQL advisory lock 内で追加テーブルを作成し、旧所属を一度だけ移す。移行記録を同時に保存し、再起動で解除済み所属が復活しないようにする。予算・申請・証憑は移行対象外。

単体テストに加え、独立した PostgreSQL で旧形式からの移行、再実行、所属の追加・解除・再読込、重複防止、財務データ保持を確認する。本番はバックアップ取得後に更新し、従来の所属・財務データ・証憑と起動結果を検証する。
