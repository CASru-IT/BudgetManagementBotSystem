# 予算追加の取消

ユーザー承認済みの方式: 履歴IDを指定し、対象・金額・取消後残高を確認してから、元の追加を残して取消記録を保存する。

- `/予算履歴 班:<班ID>`（既存 `/usage-history` と同じ一覧）に履歴IDと取消の対応関係を表示する。
- `/予算取消 履歴id:<ID> 理由:<理由>` は本人のみ操作可能な10分間の確認画面を表示する。「取り消す」で確定し「キャンセル」では変更しない。
- 有効な Admin / President / Accountant のみ。確定時にも権限・対象・残高を再確認する。
- 元と同じ班・年度・金額の減額記録を一度だけ追加。元履歴ID、実行者ID、UTC日時、理由を保存。元履歴を削除しない。
- 取消後の実残高が負、または未承認申請を差し引くと負になる場合は拒否する。
- 追加/取消/支出/申請の競合は班の更新トークンで検知し、古い確認画面からは再実行を案内する。DBの一意制約でも二重取消を防止する。
- 新規取引は追加・返金・支出・取消を区別する。既存の収入には由来がないため旧履歴として明示し、日時と金額を確認して選ぶ。返金と判明している新規取引は対象外。
- PostgreSQLの既存DBは起動時の冪等なスキーマ拡張で対応。運用資料にバックアップと単一バージョン稼働の条件を記載。

## 検討した方式

履歴ID指定を採用（ユーザー選択）。金額を入力する減額方式は再入力誤り・二重訂正を防ぎにくい。過去の残高への上書きは後続の正当な支出まで失うため採用しない。

## 今回の範囲

GitHub develop を基点に実装・テスト・文書更新・作業ブランチへのpushまで。本番デプロイと特定の履歴の実取消は含めない。
